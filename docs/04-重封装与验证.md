# 04 - 重封装与验证

## 4.1 为什么必须重封装

拼接出来的 `merged.ts` 严格来说已经**能播**，但：

- TS 容器拖动进度条体验差，很多播放器不支持
- 剪映 / Premiere 等剪辑软件对 TS 支持不稳定
- 体积偏大（944 MB vs MP4 的 901 MB）

所以最后一步是 **TS → MP4**。

关键约束：**只能透传（remux），不能解码重编码**。
因为本机 ffmpeg 只有 1 个编码器（libx264，无音频编码器），
解码重编码必然丢音频。透传则视频音频都保持原始码流，无损、快。

## 4.2 失败的路线（4 次）

| # | 命令 / 调用 | 报错 | 原因 |
| --- | --- | --- | --- |
| 1 | `ffmpeg ... -bsf:a aac_adtstoasc` | `sample rate not set` | 精简版 ffmpeg 探测不到 TS 里的音频参数，误判为 0 声道 |
| 2 | `ffmpeg ... -c:a aac` | `Unknown encoder 'aac'` | 精简版**根本没有音频编码器** |
| 3 | `ffmpeg ... -f mp2 out.mp2` | `Requested output format 'mp2' is not known` | 只有 mov/mp4 两个 muxer |
| 4 | `ffmpeg -f mp3 -i audio.mp2` | `Unknown input format: 'mp3'` | 只有 9 个 demuxer |

补充：从 TS 里手工抽出纯 ES 音频（`extract_audio.py`，426,363 个包 / 64.67 MB / `audio.mp2`），
再用 PyAV 打开：

```
av.error.InvalidDataError: [Errno 1094995529] Invalid data found when processing input
```

**纯 ES 没有容器和时基，解码器接不了**。这条路也堵死。

### 根因

本机自带 ffmpeg：

```
C:\Users\weido\AppData\Local\Programs\TRAE SOLO CN\resources\app\bin\ffmpeg.exe
```

- demuxers: 仅 9 个（asf, avi, flv, matroska, mov/mp4, mpeg, mpegts, mpegvideo）
- muxers: 仅 2 个（mov, mp4）
- encoders: 仅 1 个（libx264）

这是为体积裁剪过的构建，**不适合拿来做任意格式转换**。

## 4.3 成功的路线：PyAV 包级透传

```powershell

```

PyAV 自带完整 ffmpeg 动态库，实测版本：

```text
PyAV 17.1.0
libavutil 60.26.101 / libavcodec 62.28.101 / libavformat 62.12.101
libavdevice 62.3.101 / libavfilter 11.14.101
libswscale 9.5.101 / libswresample 6.3.101
```

### 一个反直觉的发现

同一个 `merged.ts`：

- **精简版 ffmpeg 说音频是 `0 channels / rate=0`**（所以 `-bsf:a aac_adtstoasc` 失败）
- **PyAV 正确识别为 `aac 44100 Hz stereo`**

也就是说问题不在文件，在工具。换工具就好了。

### 核心 API

```python
cout = av.open(DST, "w", format="mp4")
vout = cout.add_stream_from_template(vst)    # ← 关键
aout = cout.add_stream_from_template(ast)
```

> **注意 API 名称**：不是 `add_stream(template=vst)`。
> PyAV 17 的 `add_stream()` 至少要 1 个位置参数，传 `template=` 关键字会报
> `TypeError: add_stream() takes at least 1 positional argument (0 given)`。
> 正确的方法名是 **`add_stream_from_template()`**。

### AAC in TS → MP4 的 ADTS 问题

TS 里的 AAC 带 ADTS 头，MP4 需要裸 AAC + `AudioSpecificConfig`。
PyAV 17 在包级透传时**已经自动处理了这个转换**，实测 `aac_adtstoasc` 选项不是必需的：

```python
try:
    aout.codec_context.options = {"aac_adtstoasc": "1"}
except Exception as e:
    print("opt note:", e)      # 设置失败也无所谓，不影响结果
```

### 完整代码

```python
import av, time

SRC = r"G:\ksrec\replay\merged.ts"
DST = r"G:\ksrec\replay\replay_full.mp4"

cin = av.open(SRC)
vst = next(s for s in cin.streams if s.type == "video")
ast = next(s for s in cin.streams if s.type == "audio")

cout = av.open(DST, "w", format="mp4")
vout = cout.add_stream_from_template(vst)
aout = cout.add_stream_from_template(ast)

VID_IDX, AUD_IDX = vst.index, ast.index
count = {"v": 0, "a": 0}

for pkt in cin.demux():
    if pkt.dts is None or pkt.size == 0:
        continue
    if pkt.stream.index == VID_IDX:
        pkt.stream = vout
        count["v"] += 1
    elif pkt.stream.index == AUD_IDX:
        pkt.stream = aout
        count["a"] += 1
    else:
        continue
    cout.mux(pkt)

cout.close()
cin.close()
print("DONE v=%d a=%d" % (count["v"], count["a"]))
```

## 4.4 三项完整性验证

单纯「文件能打开」不够。这三个脚本分别从不同角度证明成品是完整的。

### ① verify_full.py — 容器与流

```text
size MB = 901.2
format: mov/mp4  duration(sec) = 5165.845326
bit_rate: 1463461
streams: 2
  [0] video h264 tb=1/90000 dur=5163.82 1280x960 fps=30 pix=yuv420p
  [1] audio aac  tb=1/44100 dur=5165.74 rate=44100 ch=2 layout=stereo fmt=fltp
  [0] video: decoded 30 frames OK
  [1] audio: decoded 30 frames OK
VERIFY_OK
```

> 踩坑：`AudioFrame` **没有 `.channels` 属性**（新版本已移除），
> 要用 `f.layout`（会打印成 `stereo`）。原脚本因此崩过一次。

### ② verify_audio.py — 音频全程解码

只抽几帧不够。这个脚本**把整条音轨解码完**，统计采样点总数，
再和容器时长对照——能抓出「音频中途截断」这种静默损坏。

```text
audio stream: aac 44100 stereo fltp
first audio frame: 2048 samples, rate 44100, stereo, pts 2514
audio frames decoded: 111235
total samples: 227809280
audio duration sec = 5165.743
AUDIO_OK
```

`227809280 / 44100 = 5165.743 s`，与容器 `5165.845 s` 差 **0.1 秒**，一致。

> 踩坑：`c.decode(audio=ast.index)` 会报 `IndexError: tuple index out of range`。
> 正确写法是**直接传流对象**：`c.decode(ast)`。

### ③ verify_timeline.py — 关键帧分布 + 音视频漂移

这个最重要。它回答两个问题：

- **中间有没有大段丢失？** → 看关键帧间隔
- **声音和画面有没有越走越偏？** → 看尾部 PTS 差

```text
=== 1) merged.ts keyframe distribution ===
keyframes: 2637  first=2.09s  last=5163.90s
span: 5161.82s = 86.03 min
keyframe gaps > 20s: NONE

=== 2) merged.ts sequential timeline ===
video last pts = 5165.84s (86.10 min)
audio last pts = 5165.75s (86.10 min)
AV drift at tail = 0.08s

=== 3) MP4 stream durations ===
mp4 audio stream duration = 5165.74s (86.10 min)
mp4 video stream duration = 5163.82s (86.06 min)
```

**2637 个关键帧、无一超过 20 秒的空洞** → 全程连贯，没有丢段。
**尾部漂移 0.08 秒** → 音画同步良好。

> 踩坑：**不要用 seek 抽样来验证时间线**。
> 第一版 `verify_timeline.py` 用 `c.seek()` 跳到若干个时间点再读 PTS，
> 结果每个点都报 `2.09s / 1.92s` —— 因为 seek 会归零时基，看到的全是同一个位置。
> 必须**顺序 demux 一遍**取末尾 PTS。
