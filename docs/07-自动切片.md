# 07 - 自动切片

从完整回放里挑出「精彩片段」，切成独立的小 MP4 文件。

## 为什么要自动挑

86 分钟的直播里，真正值得单独剪出来的可能只有十几段。全部人工过一遍不现实，
所以要先用程序把「可能精彩」的时间点找出来，再去看/再精剪。

## 思路：两条信号线

直播回放的「精彩」通常体现为两件事：

**1. 画面突变（scene change）**

镜头切换、游戏镜头拉近、弹窗、结算画面，都会让相邻帧差异突然变大。
用 `mean(|frame_t - frame_{t-1}|) / 255` 度量，超过阈值就算一次突变。

**2. 声音能量高（loud）**

主播激动、团战配音、BGM 高潮，音频 RMS 能量会显著高于平时。
按秒统计 RMS，超过「均值 + 1.5 倍标准差」的秒标为 loud。

**3. 连续 loud 段（run）**

单秒 loud 可能是噪声，但连续 3 秒以上 loud 几乎一定是真高潮。
这类段单独作为候选事件，且权重更高。

## 打分与去重

```
score = diff * 1.0 + nearby_loud_seconds * 0.25     # 来自 scene change
score = 0.6 + 0.05 * run_length                     # 来自连续 loud 段
```

按 score 降序，逐个取窗口，但要过三道关：

**1. 起点间隔**：新窗口起点与已选窗口起点相距 ≥ `MIN_GAP`，防止重叠覆盖。

**2. 分区分流（zone）**：直播里经常出现「一个静态界面持续很久」的情况——
商店/仓库/设置页一次打开就是十几分钟，画面几乎不动，但它会不断产生
loud（主播在解说），于是按分数挑会**连环选中同一张画面**。
做法：把直播按时长切成 `ZONE_SEC`（默认 600s）的区，**每区最多选 1 段**，
保证片段散布全片而不是扎堆。

**3. 画面指纹去重（frame signature）**：zone 只保证时间分散，不保证画面
不同——同一条「商店画面」可能横跨两个区。对每个候选窗口取中间一帧，
缩成 48x36 灰度签名；新窗口若与已选窗口的最小签名差 < `DUP_FRAME_DIFF`，
直接跳过（视为同一画面）。

先按 zone 尽量铺满全片；若不足 `MAX_CLIPS`，再用不查 zone 的 backfill 兜底
（仍受 MIN_GAP 和画面指纹约束）。

## 参数

改 `make_clips.py` 顶部的常量：

| 参数 | 默认 | 含义 |
|---|---|---|
| `CLIP_LEN` | 45.0 | 每段目标时长（秒） |
| `PRE_ROLL` | 6.0 | 事件点往前多留几秒做铺垫 |
| `MIN_GAP` | 90.0 | 两段起点最小间隔，防止内容重复 |
| `MAX_CLIPS` | 12 | 最多切几段 |
| `TOP_N_EVENTS` | 60 | 参与打分的候选事件上限 |
| `MAX_PER_ZONE` | 1 | 每个分区最多选几段 |
| `ZONE_SEC` | 600.0 | 分区长度（秒），控制片段的时间分散度 |
| `DUP_FRAME_DIFF` | 0.04 | 画面签名最小差，低于它视为同一画面 |
| `SCENE_THRESHOLD` | 0.28 | 画面突变判定阈值（在 `analyze.py`） |
| `ANALYZE_FPS` | 1.0 | 抽帧分析频率 |

要更多/更少的片段，改 `MAX_CLIPS`；想要更短更适合短视频平台的片段，改 `CLIP_LEN`。
觉得片段仍像「同一画面」，把 `DUP_FRAME_DIFF` 调高（更严格）；反之调低。

## 用法

```bash
# 1) 分析（约 12 分钟，只做一次）
python clipper/analyze.py
#    -> analysis.json

# 2) 预览切片计划，不实际切割
python clipper/make_clips.py --list

# 3) 实际切割
python clipper/make_clips.py
#    -> clips/clip_01_001151.mp4 ...

# 4) 校验产物
python clipper/verify_clips.py

# 5) 清理旧选区残留（改过选区参数后必跑）
python clipper/clean_clips.py

# 6) 画面查重（对缩略图两两比签名，确认没有近似重复片段）
python clipper/check_diversity.py
```

`make_clips.py` 默认跳过已存在的文件；要强制重切加 `--force`。
`verify_clips.py` 会扫整个输出目录，所以**换过选区后必须先用
`clean_clips.py` 清掉旧文件**，否则旧片段也会被一起校验/列出来。

## 关于切割的实现（最容易踩坑的地方）

切割要**快**，所以用 stream-copy（不重编码）。但 stream-copy 有两个大坑：

### 坑 1：音频丢了

最初的写法是 `c.demux(vst)` 和 `c.demux(ast)` 分开拿。结果产出的文件里
音频包只有一个空壳，解码出来 0 帧。

**原因**：PyAV 的 demuxer 是单遍的，共享一个包队列。必须先
`cin.demux()` **不带参数**拿到所有流，再用 `pkt.stream.index` 手动分发。

```python
for pkt in cin.demux():              # 不要传 stream
    if pkt.stream.index == vst.index:
        ...
    elif pkt.stream.index == ast.index:
        ...
```

### 坑 2：时间戳错乱，片段开头对不上

`seek(start)` 实际会落到 start **之前**的那个关键帧上，于是第一个视频包的
pts 比 start 小。如果直接 `pts -= start`，就会产生负时间戳和错位的音画。

**正确做法**：以「seek 后拿到的第一个视频包的 dts」作为原点，而不是用 `start`：

```python
if not started:
    vshift = -pkt.dts                      # 第一个包的 dts 归零
    ashift = -round((-vshift * vtb) / atb) # 音频用同一个墙钟时刻归零
    started = True
```

### 坑 3：B 帧导致 pts 不单调

H.264 有 B 帧，包的**解码顺序（dts）**和**显示顺序（pts）**不一致。
所以：

- **不能**按 pts 判断「是否超出窗口」，要按 dts；
- **不能**对包重排序，直接原样 shift 即可。

产出的文件里 pts 会出现 `0, 24030, 12060, 6030...` 这种回跳，这是**正常的**，
播放器按 dts 解码、按 pts 显示，画面是对的。

### 坑 4：容器 start_time 不为 0

muxer 记录的 `start_time` 取的是第一个包的 **pts**，而第一个包的 pts 往往
比 dts 大一点（有一帧多的延迟）。结果播放器显示的开头会有一小段空白偏移。

处理：切完之后再走一遍 `_normalize_start()`，读回 `start_time`，把两条流整体
平移，使 `start_time` 归零，然后用临时文件替换。

## 校验结果

```
[OK ] clip_01_000151.mp4   9.8MB v=1381(46.0s) a=978(45.4s) pk=1.023 drift=0.64s
[OK ] clip_02_000531.mp4   8.2MB v=1381(46.2s) a=978(45.4s) pk=0.907 drift=0.85s
...
files=12  bad=0  total=553s (9.2 min)
```

- `v` / `a` = 解码出的视频帧数 / 音频帧数，都不为 0 才算成功
- `pk` = 音频前 200 帧的峰值振幅，> 0.001 说明不是静音
- `drift` = 视频时长与音频时长之差，< 1.5s 算正常

### 校验本身也有坑

`verify_clips.py` 起初报「全部 NO-AUDIO」，但文件其实是好的。

**原因**：在同一个 `av.open()` 句柄上先 `decode(video)` 会把包队列抽干，
之后再 `decode(audio)` 就什么都拿不到。

**做法**：视频和音频各自 `av.open()` 一次，独立解码。这一点在写校验脚本时
很容易忽略，会把好文件误判成坏文件。

## 给片段加文字（标题条 + 弹幕）

`clipper/overlay_text.py` 在片段上叠加「片头标题条 + 飘屏弹幕 + 结尾卡片」，
然后**重编码**输出（libx264 + aac）。

```powershell
python clipper/overlay_text.py
```

- 因为 PyAV 自带的 ffmpeg 库**没有 drawtext 滤镜**（未编译 libfreetype），
  所以不能走 filter 链；方案是解码每一帧 → PIL 直接画字 → 重新编码。
- 弹幕配置在脚本顶部的 `DANMAKU` 列表：`(起始秒, 结束秒, 文案, 纵向位置, 滚动速度)`。
- 两个关键点：
  - **时间基准**：重编码时必须给每个 `VideoFrame` / `AudioFrame` 显式
    设 `time_base = 1/1000000`，否则 muxer 会用默认基准，时长元数据错乱
    （实测出现过视频被记成 200 万秒）。
  - **音频句柄独立**：和校验一样，视频/音频各开一个 `av.open()`，
    同一个句柄先解视频会把音频包队列抽干。
- 实测：60 秒 1280x960 片段，渲染约 1 分钟；输出 25 MB。
