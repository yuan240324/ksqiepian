## 坑 1：系统自带 ffmpeg 是个「残废版」

### 症状

```
Unrecognized option 'safe'                      # -f concat -safe 0
Requested output format 'mp2' is not known      # -f mp2
Unknown input format: 'mp3'                     # -f mp3
Unknown encoder 'aac'                           # -c:a aac
sample rate not set                             # -bsf:a aac_adtstoasc
```

### 根因

```
C:\Users\weido\AppData\Local\Programs\TRAE SOLO CN\resources\app\bin\ffmpeg.exe
```

这是打包裁剪过的构建：

| 能力 | 数量 | 内容 |
| --- | --- | --- |
| demuxers | 9 | asf, avi, flv, matroska, mov/mp4, mpeg, mpegts, mpegvideo |
| muxers | **2** | mov, mp4 |
| encoders | **1** | libx264 |

**没有音频编码器，没有 mp3/mp2 封装器，没有 `concat` 协议的 `-safe` 选项。**

### 解法

不要试图修补它，**换工具**。直接上 PyAV（自带完整 ffmpeg 动态库）：

```powershell
python -m pip install -i https://pypi.tuna.tsinghua.edu.cn/simple av
```

### 附带教训

它对同一个 `merged.ts` 的音频参数判断**是错的**：

```
系统 ffmpeg  : audio rate=0 ch=0  layout='0 channels'   ← 错
PyAV 17.1.0  : audio aac 44100 Hz stereo                ← 对
```

所以「ffmpeg 报参数异常」时，先怀疑工具，再怀疑文件。

## 坑 2：PyAV 的 `add_stream_from_template()`

### 症状

```python
cout.add_stream(template=vst)
# TypeError: add_stream() takes at least 1 positional argument (0 given)
```

### 根因

PyAV 17 的 `OutputContainer` 上，模板复制流的方法**不叫 `add_stream`**。

用 `dir()` 枚举拿到真实方法列表：

```python
['_add_stream_without_codec_from_template', 'add_data_stream', 'add_mux_stream',
 'add_stream', 'add_stream_from_template', 'stream_options', 'streams']
```

### 解法

```python
vout = cout.add_stream_from_template(vst)   # 位置参数直传源流
aout = cout.add_stream_from_template(ast)
```

### 附带教训

遇到 FFI 库的 API 疑问，**不要猜、不要试，直接 `dir()` 打印**。
一行代码省掉半小时。

## 坑 3：纯 ES 音频解不了码

### 症状

从 TS 里手工抽出音频 ES 存成 `audio.mp2`（426,363 包 / 64.67 MB），
用 PyAV 打开：

```
av.error.InvalidDataError: [Errno 1094995529] Invalid data found when processing input
'avcodec_send_packet()'
```

### 根因

纯 ES 流**没有容器、没有时基、没有参数集**。解码器不知道该按什么节奏喂包。

### 解法

**不要往这个方向走。** 直接在**容器层**（`merged.ts`）操作：

```python
cin = av.open(r"G:\ksrec\replay\merged.ts")     # ← 开 TS，不开 ES
```

PyAV 从 TS 里能正确拿到 `aac 44100 stereo` 的参数，之后工作正常。

## 坑 4：PowerShell 脚本里的中文导致乱码 / 解析失败

### 症状

脚本里写中文注释或中文字符串，执行时报：

```
鎵撳紑澶辫触        ← UTF-8 被按 GBK 解码的典型乱码
```

或直接 parse error 中断。

### 根因

`powershell.exe -File xxx.ps1` 读脚本时用的编码是**系统 ANSI（中文 Windows 上是 GBK）**，
而文件实际存成 UTF-8。字节被错误解释，连语法都崩了。

### 解法

**排障脚本一律写纯 ASCII 注释和字符串。**

```powershell
# 好的写法
Write-Output "SCAN_DONE"

# 不要这样
Write-Output "扫描完成"
```

如果是必须输出中文的场景，用 `-Encoding UTF8` 显式指定，或改用 Python（不会遇到这个问题）。

## 坑 5：用 `c.seek()` 验证时间线会得到全是同一个数

### 症状

写了一个时间线验证脚本，跳到若干个时间点读 PTS：

```
00:05 -> video pts 2.09s  audio pts 1.92s
30:00 -> video pts 2.09s  audio pts 1.92s    ← 怎么还是这个数
60:00 -> video pts 2.09s  audio pts 1.92s
```

看起来像「文件只有一个时间点」。

### 根因

`seek` 会把读游标定位到最近的关键帧，**并把返回包的时基归零**。
所以不管跳到哪，第一个包的 PTS 都是「该关键帧相对起点的偏移」，数值接近且有规律。

### 解法

**顺序 demux 一遍，取末尾 PTS。**

```python
lastv = lasta = None
for pkt in c.demux():                    # 不 seek，从头顺到尾
    if pkt.size == 0 or pkt.pts is None:
        continue
    if pkt.stream.index == vst.index:
        lastv = float(pkt.pts * vtb)
    elif pkt.stream.index == ast.index:
        lasta = float(pkt.pts * atb)
print(f"AV drift at tail = {abs(lastv - lasta):.2f}s")
```

再配合**关键帧间隔分布**判断中间有没有丢段：

```python
kf = [float(pkt.pts * tb) for pkt in c.demux(vst)
      if pkt.size and pkt.is_keyframe]
gaps = [(round(kf[i],1), round(kf[i+1]-kf[i],1))
        for i in range(len(kf)-1) if kf[i+1]-kf[i] > 20]
print("keyframe gaps > 20s:", gaps if gaps else "NONE")
```

### 附带教训

**「方法错了」比「文件坏了」更常见。** 测出反直觉的结果时，先检查测量方法。

## 坑 7：`c.decode(audio=ast.index)` 参数形式

### 症状

### 根因

`decode()` 的位置参数是要解码的流对象，不是索引。

### 解法

for f in c.decode(ast):     # 直接传流对象

## 坑 8：分片下载的 3 个 HTTP 502

### 症状

1293 个分片里，第 `976 / 1083 / 1148` 三个返回 502 Bad Gateway。

### 根因

CDN 边缘节点瞬时抖动，与文件无关。

### 解法

**断点续传已经让这事变得无痛——直接原样重跑。**

```text
already have: 1290, to fetch: 3
downloaded OK : 1293 / 1293
DL_DONE
```

**不要为 502 改代码。** 只要下载器是「按文件存在性续传 + 原子落盘 + 失败重试」，
重跑就是修复手段。

## 坑 9：拼接顺序被文件名排序坑

### 症状

分片拼接后整段错乱。

### 根因

`Get-ChildItem` 默认按名称排序，如果文件名是 `1.ts / 2.ts / ... / 10.ts`，
会把 `10.ts` 排在 `2.ts` 前面。

### 解法

**分片文件名一律用零填充格式 `%05d.ts`**，并显式 `Sort-Object Name`。

```python
path = os.path.join(OUTDIR, "%05d.ts" % idx)     # 00000.ts ... 01292.ts
```

```powershell
Get-ChildItem -LiteralPath $src -Filter '*.ts' | Sort-Object Name | ForEach-Object { ... }
```

## 坑 10：`auth_key` 会过期

### 症状

隔一段时间重跑下载，全部 403 Forbidden。

### 根因

m3u8 URL 上的 `auth_key` 形如：

```text
auth_key=1789826713-1566863167-0-feb9be284f667f5a403520801ef261c7
          ^^^^^^^^^^ 过期时间戳（Unix 秒）
```

### 解法

**`auth_key` 过期就回到第 2 步重新抓一次回放页**，拿新的签名 URL。
不要缓存 m3u8 URL 超过一次会话。

## 坑 11：网络探测里的 `context` 参数

### 症状

```python
urllib.request.urlopen(req, context=ssl_ctx)
# TypeError: OpenerDirector.open() got an unexpected keyword argument 'context'
```

### 根因

`context` 是 `urlopen(url, ...)` 的参数，不能越过 `OpenerDirector` 直接传给 `.open()`。

### 解法

改用 `http.client` 或 `socket` 做纯 TCP 可达性探测，避开 SSL 层。

### 实测参考（本机网络环境）

```text
OK    pypi.tuna.tsinghua.edu.cn:443
OK    mirrors.aliyun.com:443
OK    registry.npmmirror.com:443
OK    live.kuaishou.com:443
OK    api.github.com:443
OK    codeload.github.com:443
OK    raw.githubusercontent.com:443
FAIL  github.com:443                ← 超时，需要走代理/镜像
FAIL  hub.fastgit.xyz:443
```

> `github.com:443` 直连不通，但 `api.github.com` 和 `codeload.github.com` 通。
> 所以 `git push` 需要走代理或镜像，而 REST API 建仓库可以直接用。

## 坑 12：`$pid` 是 PowerShell 保留只读变量

### 症状

```powershell
$pid = 12345      # 赋值失败 / 行为异常
```

### 根因

`$pid` 由 PowerShell 预定义为当前进程 ID，**只读**，不能覆盖。

### 解法

换变量名，如 `$procId`、`$targetId`。

## 坑 13：`LS` 工具对某些路径报 os error 3

### 症状

列举目录时报「系统找不到指定的路径 (os error 3)」，但同一路径 `Get-ChildItem` 正常。

### 解法

改用 `Get-ChildItem -LiteralPath '<路径>' -Force`。
中文路径建议始终加 `-LiteralPath`。

## 小结：优先级排序的排障清单

遇到问题时按这个顺序怀疑：

1. **工具能力**（是不是 ffmpeg/PowerShell 版本裁剪了）→ 坑 1
2. **API 签名**（方法名、参数形式是不是记错了）→ 坑 2、6、7、11
3. **测量方法**（是不是 seek / 抽样把结果带偏了）→ 坑 5
4. **数据顺序**（排序、时基、单位）→ 坑 9
5. **编码问题**（脚本文件编码）→ 坑 4
6. **网络瞬时错误**（502 / 超时，重跑即可）→ 坑 8
7. **凭证时效**（auth_key 过期）→ 坑 10
8. **最后**才怀疑文件本身损坏
