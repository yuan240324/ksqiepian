> 阶段：拿到原始精彩片段（clip/raw）之后，包装成可直接发布到快手的竖屏成片。
> 本轮产出 3 条不同风格成品，素材横跨两场直播回放（9/13 笑场 + 9/16 王者荣耀直播）。

## 2. 素材怎么挑出来的

延续 `docs/07-自动切片.md` 的方法：**音频 RMS 能量聚类定候选，密抽帧人工核对定终选**。

### 2.1 9/16 王者荣耀直播（86 分钟）

对 `analysis.json` 的 571 个高能量秒做聚类排序（`score = n * (0.6 + 0.4*density)`），Top 窗口：

```text
105-137s   score=22.6  开场大厅互动（主播全程笑着聊天）
4223-4255s score=21.4  收尾抽奖/皮肤商店
283-310s   score=17.7  匹配/选人
588-615s   score=17.7  皮肤展示
658-677s   score=14.7  对局前期
719-746s   score=14.3  团战 → 赢 → 推基地
```

密抽帧（每 4s 一帧）核对后确认两条可用叙事线：

- **713-748s 团战线**：团战爆发 → 打赢 → 追击 → 上高地推基地，画面特效密集，
  适合解说风（"注意看"体正好配连续操作）。
- **129-159s 社死线**：主播表情弧线为 **大笑 → 震惊 → 捂脸 → 苦笑恢复**，
  完整的"绷不住了"情绪过山车，适合土味风大字报逐段盖章。

### 2.2 9/13 直播笑场

沿用上一轮结论：130~165s 为憋笑 → 大笑抓头 → 收敛的完整弧线，竖屏原生素材，
继续作为综艺花字风的底。

> 教训：**音频能量只能定位"哪里有事"，必须抽帧确认"是什么事"**。
> 9/16 的最高分窗口 105-137s 其实是坐着聊天（视觉平淡），而 719s 团战分数不高
> 但视觉最炸。选段要音频分和画面信息两条腿走路。

## 3. 渲染引擎：styler/style_clip.py

单脚本三风格，风格由 JSON 配置驱动（`cfg_<style>.json`）：

```powershell
# 通用入口
python styler/style_clip.py <raw.mp4> <out.mp4> <cfg.json>

# 实际三条
python styler/style_clip.py raw_0913_0130.mp4 快手_综艺花字风_笑到失控.mp4  cfg_variety.json
python styler/style_clip.py raw_0916_0713.mp4 快手_解说盘点风_团战名场面.mp4 cfg_commentary.json
python styler/style_clip.py raw_0916_0129.mp4 快手_土味老铁风_社死瞬间.mp4   cfg_rustic.json
```

### 3.1 竖屏 9:16 构图（横竖通吃）

两场素材比例不同：9/13 是 1440x1800 竖屏 4:5，9/16 是 1280x960 横屏 4:3。
统一策略：

```text
1) 原画面按宽 1080 缩放，垂直居中（content 高度 ch 自适应）
2) 上下空隙用"放大 + 高斯模糊"的同源画面填充（仿剪映背景虚化）
3) 花字/字幕条落在上/下延展带，不遮挡原始内容
```

好处：横屏游戏直播也能出竖屏成品，且字幕条有干净的落点。

### 3.2 三风格的公共动效

- **弹入**：ease-out-back（过冲回弹），0.3~0.4s 内完成，模拟综艺字幕"砸"上来
- **打字机**：解说字幕逐字出现
- **跑马灯**：土味风格底部红条循环滚动
- 全部用 PIL 自绘（`msyhbd.ttc` / `simhei.ttf`），不依赖外部 ffmpeg 滤镜

### 3.3 字体选择

```text
综艺/解说  微软雅黑 Bold (msyhbd.ttc)   字重够、笔画现代
土味       黑体 SimHei (simhei.ttf)     棱角分明、大字报感
注意       Windows 自带的 STHUPO/STXINWEI 等艺术字体本机没有，别写死
```

## 4. 本轮踩的三个坑

### 4.1 C 盘写满导致所有写盘操作失败（Errno 28 / os error 112）

工作目录原本在 `C:\Users\weido\.trae-cn\work\`，C 盘 222.5GB 用满、0 字节可用，
连写脚本本身都失败。清理 TEMP 和缩略图只够喘息。

**解法：工作区整体迁到 G 盘**（`G:\trea\切片\_工作区\`），脚本、中间产物、
渲染输出全部走 G 盘（208GB 可用）。大文件视频处理不要把工作目录放系统盘。

### 4.2 9/16 素材 mux 报 EINVAL（Invalid argument, ret=22）

**现象**：解说风渲染到一半 `cout.mux(pkt)` 抛 `av.error.ArgumentError`；
同一份代码、同一输出目录，土味风（同为 9/16 源）却正常。综艺风也正常。

**排查**：

```text
1) 先怀疑 pts 非单调 → 解码扫描三份 raw，全部单调，排除
2) 无叠加最小复现（muxtest.py）→ 仍复现，锁定与文字渲染无关
3) 对比帧间隔分布 → 找到真凶：
   raw_0916_0713.mp4: 17ms x17 / 33ms x701 / 34ms x342 / 50ms x18 混杂
                       → 量化到 1/30s 网格时 359 对帧碰撞 → 零时长包 → mux 拒收
   raw_0916_0129.mp4: 33/34ms 干净分布，0 碰撞 → 所以正常
```

**修复**（`style_clip.py` 主循环）：输出 pts 量化到 `Fraction(1, 30)` 网格，
碰撞帧直接丢弃：

```python
tick = int(round(t * FPS))
if tick <= last_tick:   # 与上一帧落进同一个 1/30 格，丢掉
    n += 1
    continue
last_tick = tick
nf.time_base = Fraction(1, FPS)   # 不再用 1/1000000
nf.pts = tick
```

时长仍按真实时间轴推进（帧数略减、时间点不变），音画保持同步。
直播回放这种"网络分片拼接"出来的源，时间戳抖动是常态，重编码前先查帧距直方图。

### 4.3 弹幕配置字段顺序

`cfg_variety.json` 里弹幕写成 `[文本, 起始, 结束, y比例, 速度]`，代码却按
`for s, e, txt, ...` 解包 → `TypeError: '<=' not supported between 'str' and 'float'`。
统一为文本在前。JSON 数组没有键名，配置格式和解析顺序要写进文档约定。

### 4.4 土味风横幅溢出 + 跑马灯被内容区遮挡

首轮渲染后抽帧发现两处视觉缺陷：

```text
1) 顶部大字报"老铁们！注意看！"最后一个感叹号溢出红色边框
   原因：横幅层宽写死 w+90，未对文字宽度做约束
   修复：banner() 增加 max_w 参数，超宽时按比例回退字号并重算层尺寸；
         星标字号改为跟随横幅高度（max(30, h*0.52)），不再写死 54
2) 底部跑马灯完全看不到
   原因：marquee 的 y 写死 1752，落进了 9:16 构图里"上下模糊延展带"的下带，
         而该带被内容区贴图覆盖（横屏源 content 高 810、cy=555，
         画面内容实际延伸到 y=1365 以下才结束 → 1752 被压在画面外）
   修复：draw_marquee() 接收 geo，y 动态取 geo.cy + geo.ch - 68，
         即紧贴内容区底边，成为压在画面上的一条红条（也更像短视频跑马灯）
```

经验：**竖屏构图里的"坐标"必须相对内容区 geo 计算，不能写死绝对像素**。
横竖屏源的 content 高度不同（1350 vs 810），写死坐标必然在某一类源上穿帮。
