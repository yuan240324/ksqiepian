#### 1.4.1 喜剧结构：三幕破功曲线

搞笑版不按"时间轴"分段，按**情绪曲线**分段，三条共用同一套模板：

```text
第一幕 装镇定   → 表面平静，但已经在憋（抖字幅度小 amp=6）
第二幕 开始崩   → 嘴角失守、声音变形（抖字 amp=9，音效接"唱片急停"）
第三幕 彻底摆烂 → 放弃抵抗、笑到抽搐（抖字 amp=12，盖章"已老实/摆烂"）
```

配合三种"笑点放大器"：

```text
① 打脸感    —— 前一秒的字和后一秒的画面对不上（"我上我也行" → 5 秒后"对不起 是我菜"）
② 停顿感    —— 梗抛完不马上接东西，故意空一拍（bgm_comedy 每 7 个音空一拍）
③ 卖惨感    —— 用反讽收尾而不是欢呼（tada 下行三和弦"没救了"）
```

#### 1.4.2 新增的 5 个喜剧视觉原语（`tex.py`）

| 原语 | 实现 | 用法 |
| --- | --- | --- |
| `jitter_text` | 整块文字高频小抖动 + 轻微旋转（正弦叠加） | 情绪花字：越憋不住抖得越狠 |
| `stamp` | 过冲回弹（0.7x 冲进 → 1.06x 反弹 → 1.0），旋转收敛 | 盖章判词："已老实"/"破功" |
| `big_arrow` | PIL 多边形 + 手绘感抖动 | 指向笑点位置 |
| `face_circle` | 多段椭圆弧拼圆（首尾留口 + 抖动） | 圈重点：手绘圈套住主播的脸 |
| `draw_caption_strip` | 圆角黑底 + 描边白字 | 黑底吐槽条 |

新增 4 个渲染分支（`render_native.py` 第 10b~10e 节）：`circles` / `arrows` / `jitters` / `stamps`，
字段格式：

```json

"arrows":  [{"t": 5.80, "x": 0.58, "y": 0.72, "ang": 150, "size": 90}],

```

#### 1.4.3 新增的 5 个喜剧音效 + 喜剧底乐（`sfx.py`）

| 音效 | 合成方式 | 笑点作用 |
| --- | --- | --- |
| `bumble` | 锯齿波低音滑音 + 颤音，尾巴掉音 | 长号"嗡——哇哇"：典型的"翻车了"提示音 |
| `slip` | 高频噪声 + 下滑哨音 | "呲溜"：滑走、失手 |

好听的不搞笑，搞笑的必须有点难听。

## 4. 本轮踩的三个坑

### 4.1 C 盘写满导致所有写盘操作失败（Errno 28 / os error 112）

工作目录原本在 `C:\Users\weido\.trae-cn\work\`，C 盘 222.5GB 用满、0 字节可用，
连写脚本本身都失败。清理 TEMP 和缩略图只够喘息。

**解法：工作区整体迁到 G 盘**（`G:\trea\切片\_工作区\`），脚本、中间产物、
渲染输出全部走 G 盘（208GB 可用）。大文件视频处理不要把工作目录放系统盘。

### 4.2 9/16 素材 mux 报 EINVAL（Invalid argument, ret=22）

**现象**：解说风渲染到一半 `cout.mux(pkt)` 抛 `av.error.ArgumentError`；
同一份代码、同一输出目录，土味风（同为 9/16 源）却正常。综艺风也正常。

**排查**：

```text
1) 先怀疑 pts 非单调 → 解码扫描三份 raw，全部单调，排除
2) 无叠加最小复现（muxtest.py）→ 仍复现，锁定与文字渲染无关
3) 对比帧间隔分布 → 找到真凶：
   raw_0916_0713.mp4: 17ms x17 / 33ms x701 / 34ms x342 / 50ms x18 混杂
                       → 量化到 1/30s 网格时 359 对帧碰撞 → 零时长包 → mux 拒收
   raw_0916_0129.mp4: 33/34ms 干净分布，0 碰撞 → 所以正常
```

**修复**（`style_clip.py` 主循环）：输出 pts 量化到 `Fraction(1, 30)` 网格，
碰撞帧直接丢弃：

```python
tick = int(round(t * FPS))
if tick <= last_tick:   # 与上一帧落进同一个 1/30 格，丢掉
    n += 1
    continue
last_tick = tick
nf.time_base = Fraction(1, FPS)   # 不再用 1/1000000
nf.pts = tick
```

时长仍按真实时间轴推进（帧数略减、时间点不变），音画保持同步。
直播回放这种"网络分片拼接"出来的源，时间戳抖动是常态，重编码前先查帧距直方图。

### 4.3 弹幕配置字段顺序

`cfg_variety.json` 里弹幕写成 `[文本, 起始, 结束, y比例, 速度]`，代码却按
`for s, e, txt, ...` 解包 → `TypeError: '<=' not supported between 'str' and 'float'`。
统一为文本在前。JSON 数组没有键名，配置格式和解析顺序要写进文档约定。

### 4.4 土味风横幅溢出 + 跑马灯被内容区遮挡

首轮渲染后抽帧发现两处视觉缺陷：

```text
1) 顶部大字报"老铁们！注意看！"最后一个感叹号溢出红色边框
   原因：横幅层宽写死 w+90，未对文字宽度做约束
   修复：banner() 增加 max_w 参数，超宽时按比例回退字号并重算层尺寸；
         星标字号改为跟随横幅高度（max(30, h*0.52)），不再写死 54
2) 底部跑马灯完全看不到
   原因：marquee 的 y 写死 1752，落进了 9:16 构图里"上下模糊延展带"的下带，
         而该带被内容区贴图覆盖（横屏源 content 高 810、cy=555，
         画面内容实际延伸到 y=1365 以下才结束 → 1752 被压在画面外）
   修复：draw_marquee() 接收 geo，y 动态取 geo.cy + geo.ch - 68，
         即紧贴内容区底边，成为压在画面上的一条红条（也更像短视频跑马灯）
```

经验：**竖屏构图里的"坐标"必须相对内容区 geo 计算，不能写死绝对像素**。
横竖屏源的 content 高度不同（1350 vs 810），写死坐标必然在某一类源上穿帮。

### 4.5 增强版：模糊延展带占近四成画面（"没填满"的根因）

**现象**：第一版抽帧复核时发现，画面上下各有约 18% 的模糊延展带，两条字幕分居
两端被模糊带割裂，花字压顶，跑马灯文字被截断。合计近四成画面是"空"的——
这正是"成片差点意思"的主因。

**根因**：第一版统一"按宽 1080 缩放 + 上下模糊补带"，对 1280x960 横屏源来说，
按宽缩放后内容只有 798px 高，剩下 1122px（58%）全是模糊带。

**修复**：重写构图函数 `layout()`，改为**裁切优先**：

```python
def layout(sw, sh, crop_top=0, crop_bot=0, fill=0.985, band=0.0):
    vh = sh - crop_top - crop_bot
    src_ar = sw / float(vh)
    MAXUP = 2.0          # Lanczos 放大上限，超过就越裁越糊
    if src_ar <= W / float(H):
        # 竖屏源：按宽铺满，上下裁一点
        s = (W * fill) / float(sw)
        cw, ch = int(round(sw * s)), int(round(vh * s))
        if ch > H:       # 太高：按高铺满并左右裁，但不超放大量
            s = min(MAXUP, (H * fill) / float(vh))
            ...
    # 横屏/方屏源：按高铺满、左右裁掉多余部分
    s = (H * fill) / float(vh)
    vw = W / s
    if s > MAXUP or vw > sw:   # 放不下：退回按宽铺
        ...
```

核心思想：**按源比例自动挑方向**，横屏源按高铺满、竖屏源按宽铺满，
让 `ch ≈ H`、`cw ≈ W`，模糊带只剩 fill 余量的 1.5%。

**验证结果**（`check_layout.py`，含越界 assert 保护）：

```text
0913竖屏1440x1800  content=1064x1891  scale=1.05  模糊带 1.5%  横裁 206px
0916横屏1280x960   content=1064x1891  scale=1.97  模糊带 1.5%  横裁 366px
0713横屏1280x960   content=1064x1891  scale=1.97  模糊带 1.5%  横裁 366px
```

模糊带从 **30~58% 降到 1.5%**。横屏源放大 1.97 倍是必要代价（源本身只有 1280x960），
2x 以内的 Lanczos 上采样观感可接受。

**连带修复的三处视觉缺陷**：

```text
1) 文字元素全部改为锚定内容区（geo.cy / geo.ch），不再按整屏定位
   花字 y = geo.cy + ch*0.32   字幕 y = geo.cy + ch - 48   角标 y = geo.cy + 20
2) 跑马灯接缝切字
   原因：原实现按 tw + 90 循环贴图，接缝处把字切一半
   修复：改用 tile = max(W, tw) 作为周期单位，字在 tile 内居中
3) 字幕条截断 + 与跑马灯重叠
   修复：自动缩字号（while size > 26 ... size -= 2），绝不截断；
         跑马灯开启时字幕自动上移到 geo.ch - 148
```

## 4.6 增强版：音效 + BGM + 节拍驱动

### 4.6.1 音效库（`sfx.py`，纯 NumPy 合成）

不依赖外部素材，用波形合成 8 种音效：

| 音效 | 合成方式 | 用途 |
| --- | --- | --- |
| whoosh | 白噪声 + 带通扫频 | 转场、推近 |
| boom | 低频正弦 + 快速衰减包络 | 爆点、震屏 |
| ding | 双正弦叠加 + 指数衰减 | 花字出现 |
| wow | 频率上滑正弦 | 反转、惊讶 |
| clap | 噪声脉冲串 | 掌声感 |
| drumroll | 密集噪声脉冲 | 悬念铺垫 |
| rise | 频率渐升 + 音量渐强 | 冲向爆点 |
| sub | 极低频正弦 | 下坠、重击 |

### 4.6.2 自造 BGM（三风格各一条）

```text
综艺：大调和弦进行 + 明亮琶音 + 四四拍底鼓
解说：小调进行 + 沉稳低音脉冲 + 稀疏打击
土味：五声音阶 + 方波主音 + 快节奏打点
```

结构：和弦垫底 → 琶音铺面 → 低音脉冲打点，三段叠加后做 tanh 软限幅。

### 4.6.3 混音策略（`audiomix.py`）

```text
原声：全段保留，在音效/爆点处做"闪避"（ducking）包络，让位给音效
BGM ：整段铺底，爆点处小幅提升（+2dB）
音效：按 beats 时间点叠加，峰值对齐
总线：三段相加 → tanh 软限幅 → 峰值归一化到 0.84
```

实测三条的混音占比：

```text
综艺  orig 0.130  bgm 0.059  sfx 0.061  -> peak 0.840
解说  orig 0.173  bgm 0.073  sfx 0.060  -> peak 0.840
土味  orig 0.122  bgm 0.061  sfx 0.064  -> peak 0.840
```

### 4.6.4 节拍驱动（`plan_*.json`）

所有视觉/听觉事件都写进 plan JSON 的 `beats` 数组，渲染时按时间点触发：

```json
"beats": [
  {"t": 0.0,  "kind": "whoosh"},   // 片头转场音
  {"t": 3.2,  "kind": "boom"},     // 爆点：震屏 + 闪白 + 咚
  {"t": 5.0,  "kind": "pop"},      // 花字出现：轻震 + 叮
  {"t": 32.5, "kind": "end"}       // 结尾卡：音乐收束
]
```

好处：**改节奏只改 JSON，不动代码**；音效、震屏、闪白、花字出现时刻天然对齐。

### 4.6.5 PyAV 音频编码坑

fltp 平面格式要求 shape 为 `(channels, samples)`，而 NumPy 默认给的是
`(samples, channels)`。直接传会报错或输出静音：

```python
blk = np.ascontiguousarray(blk.T)   # (samples, 2) -> (2, samples)
```

| 特效 | 实现 | 作用范围 |
| --- | --- | --- |

### 5.5 预检脚本的画布判定（一个必须记住的坑）

`check_comedy.py` 需要在渲染前知道"这条 plan 对应哪种画布"（1440x1800 还是 1280x960），
否则安全区数值全错。初版按文件名里的素材标签判断：

```python
key = "portrait_1440x1800" if "0913" in base else "landscape_1280x960"
```

问题：plan 文件名是 `plan_com_variety.json` / `plan_com_commentary.json`，
**里面根本没有 `0913` 这种素材标签**，于是三条全被判成横屏，
竖屏那条于是报出 3 个假错误（"segment 压到顶部状态栏"）。
排查时的一个线索很直接：输出里竖屏 plan 的 circle 坐标是 `x=422 y=768`，
而 422 = 0.33×1280、768 = 0.80×960 —— **坐标是按 1280x960 算出来的**，
说明画布选错了，不是 plan 有问题。

修复后的判定优先级：

```text
1) 文件名里直接带画布键（plan_com_variety_1440x1800.json）→ 用它
2) 按 plan 名映射（*variety → 竖屏；*commentary / *rustic → 横屏）
3) 兜底才看素材标签
```

改完重跑 → `PRE_OK`，与抽帧结果一致。**预检脚本自身的误报要能识别出来**，
否则会为了修一个不存在的错误去改正确的 plan。

| fill | 构图填充系数（默认 0.985，即保留 1.5% 余量） |

### 6.2 plan JSON 字段约定（原比例版增量）

原比例版复用增强版的全部字段，**仅新增 2 个**，其余含义不变：

| 新增字段 | 说明 |
| --- | --- |
| segments | 分段小标题：`[{txt, t, dur, cy, size}]`，左侧红底色块 + 金色描边大字，从左侧滑入；cy 为画面高度比例 |
| cy_off | 底部元素从底部往上算的比例偏移。subs 默认 0.075、marquee 默认 0.042、clock 默认 0.034 |

与增强版的两处差异：

- **`fill` / 构图相关字段失效**：输出尺寸直接取素材流宽高（`vst.codec_context.width/height`），不裁切不补边，因此没有"内容区"概念，`cy` 一律按整幅画面高度计算。
- **`push` 幅度需下调**：因为不做裁切，推近会直接吃掉素材自带黑边/平台栏，原比例版统一压到 0.04~0.065。

> 原比例版之所以要新增 `cy_off`：竖屏素材右侧有 160px 纯黑，底部又满到最底，
> 字幕条如果沿用增强版的"贴底 48px"会顶出画面外，所以底部三件套（字幕/跑马灯/时间戳）
> 全部改为按高度比例定位，各条 plan 可分别微调。

### 6.3 plan JSON 字段约定（搞笑版增量）

搞笑版继续复用上面全部字段，**再新增 4 个**，全部是"喜剧元素"，坐标一律按整幅画面比例：

| 新增字段 | 说明 |
| --- | --- |
| circles | 手绘圈重点：`[{t, dur, x, y, r, sw}]`，x/y 是圈的圆心比例，**必须落在主播脸上** |
| arrows | 手绘箭头：`[{t, dur, x, y, ang, size, color}]`，ang 为指向角度（0=右，90=下） |
| jitters | 抖字：`[{txt, t, dur, cx, cy, size, amp, seed, fill}]`，amp 为抖动幅度（6~12 递增表示越来越憋不住） |
| stamps | 盖章判词：`[{txt, t, dur, x, y, size, rot, color}]`，rot 为初始旋转角，落定时收敛到 rot×0.35 |

另外 `style` 多了一个取值：`"comedy"`，走 `bgm_comedy` 底乐。

坐标速查（这两条素材的真人位置，写喜剧元素时的唯一依据）：

```text
9/13 竖屏 1440x1800   脸 ≈ (0.33, 0.80)   真人实拍区从约 50% 高度开始
9/16 横屏 1280x960    脸 ≈ (0.10, 0.88)   真人小窗在左下角
```

> 反面教训：不要凭"画面正中"直觉给 cx/cy 填 0.5 —— 这两条素材的正中是游戏画面，
> 圈上去就是圈在无关的游戏 UI 上。
